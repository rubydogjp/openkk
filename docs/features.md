# オープン会計 — 機能カタログ

個人事業主向け複式簿記ライブラリ「オープン会計」が提供する機能の全体像。

---

## 1. 会計期間管理 (Fiscal Period Management)

| 機能           | 説明                                                                                                                                                                                                                                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 期間の作成     | 任意の開始日・終了日で会計期間を作成                                                                                                                                                                                                                                                 |
| 期間の選択     | 複数期間を持ちつつ対象期間を切り替え                                                                                                                                                                                                                                                 |
| 期間の削除     | 開始前 (`pre_opening`) の期間だけ、期間を開始の手順から削除できる (`fiscalPeriods.remove`)                                                                                                                                                                                           |
| 期間フェーズ   | `pre_opening` → `journalizing` → `pre_closing` → `post_closing`                                                                                                                                                                                                                      |
| バックアップ   | 会計期間のデータを、そのまま帳簿のファイル (`<期間名>.openkk`) として書き出す。どの製品でも「次の期間へ」の手順から出せる。無印版は左上の「バックアップ」ボタン、ほかの製品は左上の期間のメニューの「バックアップ」から、いつでも出せる (下の「バックアップ」)。期間の状態は変えない |
| ロック判定     | `buildPeriodLockMessage` でステージ別の編集可否を判定                                                                                                                                                                                                                                |
| 以前の圧縮保存 | 圧縮保存の操作も、圧縮保存済みかどうかの管理もなくした。以前に圧縮保存した期間は、読むときにふつうの期間として扱う (日付の重なりの確かめにも入る)。データを削除済み (`purged`) の期間は知らせだけを出し、保存してあるファイルを取り込むと新しい期間として見られる                    |

## 2. 仕訳入力 (Journal Entry Management)

| 機能               | 説明                                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| 仕訳の作成         | 借方・貸方・金額・摘要・取引先・税区分・事業区分を入力                                                        |
| 複合仕訳           | 1 仕訳に複数の借方/貸方明細行 (`lines[]`) を持てる                                                            |
| 取引先と区分       | 取引先・税区分・事業区分は、1 つの仕訳で 1 つ。違うときは別の仕訳に分ける (下の「取引先と区分は仕訳で 1 つ」) |
| 月次ナビゲーション | 月単位でページネーションして表示                                                                              |
| 仕訳の編集         | 行クリックでドロワーを開き各フィールドを変更                                                                  |
| 仕訳の削除         | ドロワー内の削除ボタン → 確認ダイアログで実行                                                                 |
| 事業按分率         | 0–100%（小数可）で指定し、期末に個人負担分を振替                                                              |
| 簡単入力ガイド     | テンプレートから借方・貸方科目を自動補完するウィザード                                                        |

### 取引先と区分は仕訳で 1 つ

取引先・税区分・事業区分は、明細の行ごとに保存するが、1 つの仕訳の中ではどの行も同じ値にする。手数料だけ取引先が違う、というときは仕訳を分ける。

- 受ける側は、仕訳の作成・変更・まとめての取り込みで、行どうしの値が違う入力を 400 で断る (`assertEditableEntryInput`)
- 編集画面の欄は仕訳で 1 つずつで、保存するときはどの行にも同じ値を書く
- シートと CSV は、仕訳で 1 つの値をその仕訳のどの行にも出す。取り込みでは、同じ仕訳番号の行で値がそろっていなければ、取り込めない行として知らせる
- そろえる値は、行の順で最初に入っている値。ただし税区分と事業区分は「対象外」より他の値を優先する (どの行も「対象外」ならそのまま。`entrySharedLineValues`)
- JSON と以前の形式の CSV は、行ごとに値が違っていても、この決まりでそろえて取り込む
- 前からある、行どうしの値が違う仕訳は、そのまま読める (本締め・引き継ぎ・バックアップの取り込みは断らない)。編集画面とシートにはこの決まりで選んだ値が出て、保存や上書きをしたときにその値にそろう。編集画面では、区分の欄の下に「この仕訳は、行ごとに税区分が違います。保存すると、どの行もここの値にそろいます。」と出す (開いたときの記録で決まり、編集中に出たり消えたりしない)

## 3. ファイルインポート / エクスポート (Data Portability)

仕訳の画面の右上の「シート」ボタンから、会計期間の仕訳を 1 枚で見るシートの画面 (`/entries?view=sheet`) に移る。書き出し・取り込みはこの画面で行う。

シートは左のメニューを出さずに画面いっぱいに使い、上の帯の「月ごと」で元の画面に戻る。上に列の記号 (A, B, C…)、左に行の番号 (1, 2, 3…) を出す。項目名の行が 1 行目で、行の番号は CSV を表計算ソフトで開いたときの番号と同じになる。金額は画面でだけ桁区切りを付け、CSV の中身は数字のままにする。行を押すと、その仕訳の編集が開く。仮締めや本締めのあとの期間では、月ごとの一覧でもシートでも、行を押すと編集できない形で仕訳の中身 (長い摘要や取引先も全文) が開く。

| 機能                | 形式           | 説明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------------------- | -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 表の形              | CSV (`.csv`)   | 1 行 = 借方・貸方の 1 組。列は 日付・借方科目・借方金額・貸方科目・貸方金額・摘要・取引先・税区分・事業区分・事業割合・仕訳番号 (読むときは列の名前で探すので、順は問わない)。複合仕訳は同じ仕訳番号の行が続き、日付・摘要・事業割合と、取引先・税区分・事業区分はどの行も同じにする (`journal-table.ts`)                                                                                                                                                                                                                                                                                                                                        |
| エクスポート        | CSV            | 期間内の仕訳 (自動の行を除く) を表の形で書き出す。金額は数字だけ、事業割合は `80` のように書く                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| インポート (上書き) | CSV            | 仕訳番号で今の仕訳と突き合わせ、追加・変更・削除の件数をダイアログ「CSV での上書き」で確かめてから上書きする。違いがなければ「今の仕訳と同じです」と知らせる。仕訳番号が空の行は新しい仕訳、ファイルにない仕訳は消す。税区分・事業区分が一覧にないときは、その文字のまま「カスタム(…)」の区分として受け付ける (画面・CSV・帳票でも「カスタム(…)」と出し、書き出した CSV を取り込み直しても変わらない)。仕訳番号の列そのものがないファイル (明細から作った CSV など) は、今の仕訳を変えず、ダイアログ「仕訳の追加」で件数を確かめてから足すだけにする。読めない行があれば、ダイアログ「CSV を取り込めません」に行の番号と理由を並べ、何も変えない |
| 科目の書き方        | CSV            | 科目名で書く。名前が重なる科目は `消耗品費（売上原価）`・`貸倒引当金（固定資産）` のように区分を付ける (`buildBookAccountLabels`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| JSON (非推奨)       | JSON (`.json`) | 互換のために残す。`schema: "openkk-journal-v1"` 形式で書き出し、取り込みは `localId` が既存仕訳と重複しないものだけ足す。`事業主借` は種別が `liability` でも純資産として取り込む                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 以前の形式の CSV    | CSV (`.csv`)   | `localId` 列のある以前の CSV は読むだけ残す (`importEntriesFromLegacyCsv`)。書き出した時点の控えなので上書きにせず、JSON と同じく足すだけで取り込む                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

## 5. 期首繰越 / 再振替 (Opening Carryover)

| 機能                   | 説明                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 再振替仕訳の登録       | 翌期作成時に未払・前払などの候補から対象を選択。在庫 (商品・棚卸資産・製品・原材料・仕掛品) は期末のしーくりくりしーで扱うので候補に出さない (受ける側も再振替に使わない)。期首仕訳は後から編集可能                                                                                                                                                  |
| バーチャル行として表示 | 期首の月の仕訳一覧に「再振替」バッジ付きで自動表示                                                                                                                                                                                                                                                                                                   |
| 期首残高の入力         | 資産・負債の期首残高 (`opening.balanceLines`) を貸借一致で入力                                                                                                                                                                                                                                                                                       |
| 引き継ぎの上書き       | 開始後の期間でも、期首のBSの手順から引き継ぎ元 (すぐ前の期間だけ。終了日の翌日から引き継ぎ先が始まるもの) を選び、期首のBS・再振替・固定資産を選んだものだけ上書きする (`fiscalPeriods.applyCarryover`)。固定資産は、その期間より前に買ったものだけを入れ替え、その期間に買ったものは残す (確認に入れ替わる件数を出す)。仮締めまで何度でもやり直せる |
| 別の帳簿からの引き継ぎ | 別の帳簿にある期間 (本締めと書類の受け取りを終えたもの) を圧縮保存と同じ形で渡し、期首のBS・再振替・固定資産を引き継ぐ (`fiscalPeriods.applyCarryoverFromArchive`)。再振替は渡した仕訳の並び順で選ぶ。openkk-cli の `opening carry` と、会計期間ごとに帳簿を分ける `books-db-adapter` が使う                                                         |

## 6. 締め処理フロー (Closing Flow)

ステップ UI が期間の状態に合わせて次のステップへ誘導する。`deriveSteps` は 6 ステップ構成で、仮締め (pre closing) は独立ステップではなく「日々の仕訳」ステップの完了操作として扱う。

| ステップ          | 内容                                                                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 期間を開始     | 期間設定の確認 (開始日・終了日)                                                                                                                                |
| 2. 期首のBSを入力 | 貸借対照表の期首残高を入力。入力欄は決算書の行の名前で並ぶ。保存し直しても、引き継いだ・保存した科目 (普通預金・商品など) のまま記録し、行の名前に書き換えない |
| 3. 日々の仕訳     | 仕訳の入力・インポート・進捗グラフの確認。完了時に `runPreClosing` で仮締めし仮の帳票3点を生成                                                                 |
| 4. 本締め         | 最終帳票3点を生成・財務諸表サマリーを表示。本締め後は変更不可                                                                                                  |
| 5. 書類を受け取る | 生成済み帳票を確認し受取完了                                                                                                                                   |
| 6. 次の期間へ     | BS 繰越・再振替・固定資産データの引き継ぎを確認。バックアップのダウンロードもここで行う                                                                        |

「次の期間へ」は、次の期間をもう作ってあれば入力できない見た目にする。欄の並びと位置はそのままで、作成済みの期間の名前と日付を薄く出し、「作成済みです」と添え、「次の期間を作成」の場所に「次の期間を開く」を出す。次の期間は、この期間の終わりより後に始まる期間のうちいちばん早く始まるもので、提案する日付 (終わりの翌日から 1 年) と重なるもの (`findCreatedNextFiscalPeriod`。データを削除済みの期間は数えない)。

仮締め (`runPreClosing`) は `journalizing → pre_closing`、本締め (`runFinal`) は `pre_closing → post_closing` に遷移させる。本締め前なら `cancelPreClosing` で記帳に戻れる。

減価償却・再振替・家事按分の自動仕訳を仮帳票に含め、本締め時に保存する。サーバーが保存済みデータから再計算して検証するため、仮帳票と確定帳票の数字は一致する。

## 7. 財務帳票 (Financial Reports)

| 帳票                            | 説明                                                         |
| ------------------------------- | ------------------------------------------------------------ |
| 仕訳帳 (Journal)                | 全仕訳を日付順に印刷用 HTML として生成                       |
| 総勘定元帳 (General Ledger)     | 科目ごとの残高推移を印刷用 HTML として生成                   |
| 財務諸表 (Financial Statements) | 損益計算書 (P/L) + 貸借対照表 (B/S) を印刷用 HTML として生成 |

- どの帳票も、どのページの上の端にも「2026年分 (2026/01/01〜2026/12/31)」と「作成日 2027/02/10」を出す。作成日はアプリの時計 (設定の今日)。期間名は 30 文字を超えると縮める。氏名は入れない
- 本締めの前 (記帳中・仮締め) に作った帳票は、ページの題の横に「決算前」の印を付ける (`isProvisionalReport`)。本締めのあとの帳票には付けない
- ページは行の高さを見積もって分け、表がページ番号にかからないようにする (`print-layout.ts`)
- 総勘定元帳は、残高の前に「借/貸」の列を置き、残高がどちらの側にあるかを示す
- 損益計算書の売上原価は、2 期首棚卸高・5 期末棚卸高のほかの売上原価の科目 (仕入・仕入値引戻し高・外注加工費など) を全部 3 仕入金額に入れ、4 = 2 + 3、6 = 4 − 5 が合うようにする。経費の残高がマイナスの科目も、その行にマイナスで出し、行の合計が 32 計と合うようにする

生成した HTML は `PrintPort.openPrint(html)` 経由でブラウザの印刷ダイアログに渡す。帳票内のすべてのユーザーデータは HTMLエスケープ済み (`escapeHtml`)。

## 9. ストレージ (Storage)

| アダプタ            | 用途                                                     | 永続化                                           |
| ------------------- | -------------------------------------------------------- | ------------------------------------------------ |
| `legacy-db-adapter` | 26.3 までの SQLite OPFS (ブラウザ内の 1 つの DB)         | 前の版のデータ。移すときに読むだけ               |
| `memory-db-adapter` | インメモリ (揮発)                                        | ページリロードでリセット                         |
| `book-db-adapter`   | 帳簿 1 冊 (`.openkk`、SQLite) をブラウザのメモリ上に開く | 開いた側が書き出して保存する                     |
| `books-db-adapter`  | 会計期間ごとの帳簿に振り分ける (無印版)                  | 変わった帳簿を置き場 (ブラウザの中) へ自動で保存 |
| `disk-db-adapter`   | `.openkk` ファイル (SQLite) を Node で開く               | ファイルそのもの (openkk-cli)                    |

`legacy-db-adapter` のほかは `OpenkkDbPort` を実装しており差し替え可能 (`legacy-db-adapter` は前の版の DB を書き出すだけ)。`.openkk` は中身が同じ SQLite なので、無印版が「バックアップ」で書き出したファイルを openkk-cli で扱い、また無印版に取り込める。SQL・マイグレーション・最後に変えた時刻の記録は `sqlite-db-adapter` で共有する。無印版は 26.3 まで `legacy-db-adapter` の 1 つの DB にすべての期間を置いていた。今は期間ごとの帳簿に分けて置き、`legacy-db-adapter` は前の版の DB を移すときに読むだけ。読めない期間があれば、その期間だけ飛ばして起動し、期間の選択に「移せませんでした」の行として出す (前の DB は消さない)。同じ日付で中身も同じ期間が 2 つあれば (圧縮保存した期間の zip を取り込み直してできたもの)、圧縮保存したもとの期間だけを移して 1 つにまとめ、まとめた期間を覚えておく。中身が違えば両方移す。

## 10. デフォルトマスターデータ (Built-in Master Data)

オープン会計 は個人事業主の青色申告を想定したデフォルト勘定科目・税区分・事業区分を内蔵する。

| データ   | 定数                          | 内容                                                                |
| -------- | ----------------------------- | ------------------------------------------------------------------- |
| 勘定科目 | `DEFAULT_BOOK_ACCOUNTS`       | 資産・負債・純資産・収益・費用の主要科目 219 件（専従者給与を含む） |
| 税区分   | `DEFAULT_TAX_CATEGORIES`      | 課税 10% / 軽減税率 8% / 免税 / 非課税 / 対象外（5件）              |
| 事業区分 | `DEFAULT_BUSINESS_CATEGORIES` | 第1〜第6種・対象外 (みなし仕入率区分、7件)                          |

勘定科目は既定IDのみ、税区分・事業区分は既定IDと利用者定義値を受け付ける。

この 3 つは「科目と区分の版」(`MASTER_SETS`) として持つ。元は `resources/gen/master-sets/` (`index.json` に版の ID・表示名・効き始める日、版ごとの中身のファイル) で、`npm run gen-master-data` で engine と driver に生成する。今の版は `jp-2026`「2026年版」の 1 つだけで、`DEFAULT_*` は最新の版の中身を指す。制度が変わったら新しい版を足し、古い版は消さない。ID は版をまたいで変えない (同じ物なら名前が変わっても同じ ID)。

- 会計期間は版の ID (`masterSetId`) を持つ。作るとき (`create`・`createNext`) にバックエンドが開始日で決める (開始日以前から効く版のうち最新)。使う側は送らない。版を持たない保存済みの期間 (26.3 までの DB・zip、版を足す前の帳簿) は `jp-2026` と読む。`.openkk` と zip の取り込みは、ファイルにある版をそのまま保つ (知らない版でも)
- 手順 1 に「科目と区分」の行をいつも置き、版の表示名を出す。開始前と記帳中で、期間の開始日以前から効く今より新しい版があるときだけ、同じ行の右に「<版>に切り替える」を出す (確認「科目と区分の切り替え」、本文「仕訳はそのままです。<版>にない科目や区分は「カスタム(…)」と出ます。」)。切り替えても仕訳は書き換えない。仮締めのあとは変えられない
- 仕訳の科目の候補は、その期間の版の科目だけ。版にない科目を使った仕訳は、ほかの版から名前と種類を引いて表示・帳票に使い、CSV には「カスタム(名前)」と書く (取り込みは「カスタム(名前)」も名前だけも受け付ける)。どの版にもない科目 ID は「カスタム(ID)」。税区分・事業区分は、その期間の版にないものを「カスタム(…)」と出す

## バンドル一覧

版は実行時切替ではなく **バンドル（別パッケージのアプリ）** で分ける。`bundle`（版）と `brand`（サイト URL・アカウントアイコン）は独立した概念。

| bundle     | パッケージ                                                       | 表示名 (`bundleLabel`) | DB                            | シードデータ               | 認証     |
| ---------- | ---------------------------------------------------------------- | ---------------------- | ----------------------------- | -------------------------- | -------- |
| `sim`      | `@rubydogjp/openkk-bundle-sim` (`packages/bundle-sim`)           | Sim版                  | memory + 固定時計             | なし (任意に作成)          | embedded |
| `demo`     | `@rubydogjp/openkk-bundle-demo` (`packages/bundle-demo`)         | デモ版                 | memory + 固定時計             | あり (buildOpenkkDemoSeed) | embedded |
| `original` | `@rubydogjp/openkk-bundle-original` (`packages/bundle-original`) | 無印版                 | 期間ごとの帳簿 (ブラウザの中) | なし                       | embedded |

無印版は、データをブラウザの中に置く。置き方は環境で変えない。ブラウザによっては、しばらく (Safari では 7 日ほど) 開かないとデータを消すことがあるので、重ねて出す知らせ「データはこのブラウザの中だけにあります」で伝え (閉じるまで、開くたびに出す)、利用者が自分でファイルにバックアップする。左上 (ほかの版で「オープン会計」と版の名前が出る場所) に「バックアップ」ボタンを置き、今の会計期間の帳簿を `<期間名>.openkk` として書き出す。保存先を選ぶ窓が使えるブラウザ (Chrome・Edge など) ではその窓で書き、書けたときだけバックアップ済みにする (窓を閉じたら何も変えない)。窓が使えないブラウザでは、スマホは共有シート、それ以外はダウンロードで渡す (ダウンロードは、ファイルができたかどうかを確かめられない)。ボタンの下に「バックアップしていない変更があります」か「前回 11/3」を出し、変更があって 30 日バックアップしていなければ、重ねて出す知らせで伝える (`OpenkkBookFilesPort`)。

バックアップしたファイルは、期間の選択の「ファイル」→「ファイルを取り込む」で取り込む。取り込みは復元で、今のデータと混ぜない。まだない期間は足し、同じ期間はダイアログ「ファイルでの上書き」で確かめてから、ファイルを優先して上書きする (選べるのは「キャンセル」と「上書きする」)。今のデータと同じなら「今のデータと同じです。」と出して何もしない。アプリの側にバックアップしていない変更があれば、それが失われることを知らせる。別に作られた同じ日付の期間は、今の帳簿が失われることを知らせる。日付が重なるだけの期間は取り込まない。同じブラウザでは 1 つのタブでだけ動き、2 つ目のタブは 1 つ目を閉じるまで待つ。取り込みが済んだあとで、ほかの帳簿をブラウザの中に保存できなかったときは、ページを読み直さずに画面の中だけで読み直す (保存できていない帳簿は消えない。保存できなかったことは、知らせ「ブラウザに保存できませんでした」が伝え、「もう一度」で保存し直せる)。前の版 (26.3 まで) のデータは、新しい版を初めて開いたときに期間ごとの帳簿に分けて移す (前のデータは消さない)。移すときに、前の版のデータ全体と期間ごとの中身の指紋、移した帳簿の印を覚えておき、起動のたびに前の版のデータを読み直す (書き込まない)。引っ越しのあとで前の版が期間を変えたり足したりしていれば、下の知らせ「前の版で「2026年分」が変わっています」の「移し直す」で、その期間を移し直す。アプリの側でもその期間を変えていたときだけ、ダイアログ「前の版での上書き」で失われる変更を確かめる。前の版で消えた期間は消さず、知らせ「前の版で「…」が消えています。こちらは消していません」だけを出す。読めない期間があれば、その期間だけ飛ばして起動し、期間の選択に「移せませんでした」の行として出す。ブラウザの中の帳簿が読めないときも、同じ形の行 (「読み込めませんでした」) で出す。その期間のバックアップを取り込むと、読めない帳簿をファイルで上書きして直せる (新しい版で作られた帳簿は上書きしない)。取り込むファイルは、中身を確かめながら読んで帳簿を作り直してから入れる。64MB を超えるファイルと、中身が今の決まりに合わないファイルは「オープン会計の帳簿ではありません」として断る。

どの製品にも圧縮保存の操作はない。「次の期間へ」の手順に、その会計期間のデータをそのままファイル (`.openkk`) として出す「バックアップをダウンロード」を置く (期間の状態は変えない)。無印版では、左上の「バックアップ」と同じファイルになる。Sim版・デモ版など、データを帳簿のファイルとして持たない製品では、バックエンドから読んだ記録で帳簿のファイルを組み立てる (`records-book-files-adapter`)。期間の ID はそのまま保つ。デモ版だけは、だれが開いても期間の ID が同じなので、書き出すたびにファイルの中の ID を付け直す (無関係なファイルどうしが、同じ期間と見なされないように)。

バックアップしたファイルは、どの製品でも期間の選択の「ファイル」→「ファイルを取り込む」から取り込める。データを帳簿のファイルとして持たない製品では、新しい期間として足すだけで、日付の重なる期間があれば取り込まない (上書きしない)。そのため、これらの製品の「次の期間へ」の手順では、バックアップを「取り込める」とは案内せず、「この会計期間のデータを、ファイル (…) として手元に残せます。」とだけ出す (`backupFileHint`)。前の版で作った圧縮済みファイル (zip) も、同じ入口から取り込める (中身が zip なら圧縮済みファイルとして読み、新しい期間として足す。日付の重なる期間があれば断る)。

製品は `bundle-<名前>` という箱で、動く形 (`client-browser`) と口の実装と設定を選んで束ねる。ブラウザで動かす配線は `@rubydogjp/openkk-client-browser`（`packages/client-browser`）に集約。

## 知らせ (Notices)

知らせは、画面の物を動かさないように前面へ重ねて出す (`OpenkkShellLayout` の中の下の中央。仕訳や固定資産を編集する画面が開いている間は、その左の空きか、下のボタンの上)。画面の流れの中には差し込まない。

| 種類                   | 見た目       | 閉じ方                                                                                                          | 例                                                                                |
| ---------------------- | ------------ | --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| うまくいった結果       | 緑のチェック | 5 秒で消える。× でも閉じる                                                                                      | 取り込みました・上書きしました・書き出しました                                    |
| 確かめてほしいこと     | 黄色の三角   | × で閉じる (閉じたものは、次に開いたときにまた出す。前の版から移せなかった期間の知らせは、閉じたらもう出さない) | 30 日バックアップしていない・読めない帳簿がある・前の版から移せなかった期間がある |
| うまくいかなかったこと | 赤のバツ     | 結果は × で閉じる。直るまで出すものは × なし                                                                    | 取り込めませんでした・ブラウザに保存できない・データを読み込めない                |

同時に出すのは 3 枚までで、新しいものを下に足す。直るまで出すものを優先して残す。画面から出すときは `useOpenkkNotices().show()` (結果) か `useOpenkkStandingNotice()` (状態に合わせて出し入れ) を使う。CSV の上書きの確認と、取り込めない行の一覧はダイアログで出す。入力欄のそばのエラーは、操作の途中に出るものなので、ここには入れない。
